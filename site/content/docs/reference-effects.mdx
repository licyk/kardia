## 可接受的效应形态 [#shapes]

`fiber.ts:64-76`：

```ts
type Disposable<T = any> = () => T
type SyncEffect<T>  = Disposable<T> | Iterable<Disposable<T>, void, void>
type AsyncEffect<T> = Promise<Disposable<T>> | AsyncIterable<Disposable<T>, void, void>
type Effect<T>      = SyncEffect<T> | AsyncEffect<T>
```

因此，一个效应（effect）回调可以返回：

| 回调返回 | 论文中的解读 |
|---|---|
| 一个函数 | 效应函数 𝔈Γ（返回的函数即逆操作） |
| `undefined`/`null` | 恒等效应（无需撤销） |
| 一个 `Promise<function>` | 异步效应函数 |
| 产出撤销函数（disposer）的同步生成器 | 效应迭代器 ℑΓ，同步运行至结束 |
| 产出撤销函数的异步生成器 | 带**迭代边界**、在边界处检查守卫的效应迭代器 |

其他任何返回值都会抛出 `TypeError('Invalid effect')`。

## 引擎 `_execute(runner)` [#execute]

`fiber.ts:240-290`。`EffectRunner { epoch, execute, collect, getOuterStack }` 抽象了引擎的两个使用者：单次 `ctx.effect` 调用，以及纤程（fiber）的整个 `apply`：

- `execute()` 产生效应值；
- `collect(dispose)` 记录一个被产出的逆操作；
- `epoch` 是**守卫**。对于异步迭代器，循环条件是 `while (runner.epoch === oldEpoch)`；纪元（epoch）改变时，循环在当前迭代落地后停止，并调用 `iter.return()` 以便生成器的 `finally` 块得以运行（`fiber.ts:269-285`）。

**同步迭代器不可中断**（没有守卫检查）；在单线程宿主中它们本来也无法被中断。每次 `collect` 都会做类型检查（`safeCollect`）。

`composeError(…, getOuterStack)` 把错误栈与效应或插件*创建*处捕获的栈（`buildOuterStack`）拼接起来，生成指向用户 `ctx.plugin(...)`/`ctx.effect(...)` 调用点的长栈追踪。这纯粹是开发体验上的处理，且是 JS 特有的。

## `fiber.effect(execute, label)`：被追踪的效应 [#fiber-effect]

`fiber.ts:292-357`。`ctx.effect` 就是 `ctx.fiber.effect`（由 `ReflectService` 混入）。逐步说明：

<Steps>
<Step>
`assertActive()`：`uid` 为 `null`（已移除）的纤程不能创建效应（`CordisError('INACTIVE_EFFECT')`）。
</Step>
<Step>
一个局部列表 `disposables` 和一个局部 `dispose()`，后者**按逆序**运行它们。若其中一个返回 promise，其余的会串接在它之后（顺序 LIFO，`fiber.ts:298-311`）。
</Step>
<Step>
用于内省的 `EffectMeta { label, children }`（`fiber.getEffects()`，供工具使用）。
</Step>
<Step>
一个 runner，其 `epoch` 是布尔值（算法 1 中的 `armed`），其 `collect`：
- 把撤销函数推入局部列表，
- **将其从纤程的顶层列表中移除**（`this._disposables.delete(dispose)`），即所有权转移（见[下文](#ownership)），
- 记录子级元数据。
</Step>
<Step>
执行。若同步抛出，释放（dispose）已收集的部分并重新抛出。
</Step>
<Step>
异步失败：`task.catch(dispose)`。失败的异步效应会回滚它已收集的部分，错误被记录到日志，而不是作为未处理的拒绝留下。
</Step>
<Step>
构建返回的**包装器**（即撤销函数）：

```ts
wrapper = () => { if (!runner.epoch) return; runner.epoch = false;
                  return task ? task.then(dispose) : dispose() }
```

- 至多一次（`epoch` 翻转为 `false`），即定理 7 的可靠性不变式；
- 翻转 `epoch` 也会让进行中的异步迭代器在下一个边界处停止；
- 若初始化仍在运行，释放会先等待它完成（`task.then(dispose)`）。
</Step>
<Step>
`wrapper.then(...)` 使撤销函数**可被 await**：`await ctx.effect(...)` 等待初始化完成，并 resolve 为一个撤销函数。
</Step>
<Step>
`disposables.push(this._disposables.push(wrapper))`：包装器被注册到**纤程的**列表中，而把它从该列表移除的函数是第一个局部撤销函数（因此手动释放一个效应也会把它从纤程中注销）。
</Step>
</Steps>

### 嵌套与所有权转移 [#ownership]

在另一个效应的回调中调用 `ctx.effect`，会先把内层包装器注册到纤程的列表中。若外层回调**产出或返回**该包装器，`collect` 会转移所有权：包装器离开纤程的列表，成为外层效应的一部分。若它未被产出，则仍是纤程的直接子项。这在*不*嵌套效应作用域的前提下实现了论文的“父级组合”（`ctx.dispose ← dispose ∘ ctx.dispose`）：纤程的累加器就是 `DisposableList` `fiber._disposables`。

```ts
ctx.effect(function* () {
  yield ctx.on('foo', handler)        // ctx.on returns an effect wrapper → owned by this effect
  yield ctx.provide('bar', value)     // ditto
  yield () => console.log('cleanup')  // plain inverse
})
```

## `DisposableList` [#disposable-list]

`utils.ts:5-40`。一个保持插入顺序的 `Map<number, T>` 加上一个 `WeakMap<T, number>`：

- `push(v)` 返回一个移除函数 `() => map.delete(sn)`；
- `delete(v)` 按身份移除；
- `clear()` 以**逆序**（LIFO）返回所有值并清空列表。

它用于纤程的撤销函数、runtime 的纤程列表以及每个纤程的钩子列表。它是论文 §3.4.2 中“以新鲜 id 插入、按 id 移除”的可交换键设计的一个实例（见[上下文范式](/docs/concepts-context-paradigm)）。

## 纤程级累加器与论文的对照 [#accumulator]

纤程的累加器不是一个组合好的闭包，而是列表 `fiber._disposables`。卸载时（`fiber.ts:488-498`）：

```ts
await Promise.all(this._disposables.clear().map(async (dispose) => {
  await composeError(async (info) => { await Promise.resolve(); …; await dispose() })
  // errors are logged, not propagated
}))
```

撤销函数**按逆序发起，但并发运行**；每个都在一个微任务之后开始。在单个效应内部，它们是顺序 LIFO 的。论文承认了这一点（“`fiber.dispose` initiates a fiber's effects concurrently”，§5.1.3），并且在独立性结果下这是可靠的（定理 43：独立效应的逆操作可以按任意顺序运行；见[元理论](/docs/concepts-metatheory)）。

<Callout type="warn">
因此，*同一个*逻辑效应内部的有序拆除，必须通过把它们组合进同一个 `ctx.effect`（生成器）来表达。
</Callout>

## 错误处理汇总 [#errors]

| 情形 | 行为 |
|---|---|
| 效应回调中同步抛出 | 运行已收集的撤销函数，错误重新抛给调用方 |
| 效应中的异步拒绝 | 运行已收集的撤销函数，记录错误 |
| 产出了无效值 | `TypeError('Invalid effect')` |
| 纤程卸载期间某个撤销函数出错 | 记录日志；其他撤销函数照常运行（`tests/fiber.spec.ts: 'dispose error'`、`service-dispose.spec.ts: 'releases dependencies after a cleanup error'`） |
| 在已移除的纤程上创建效应 | `CordisError INACTIVE_EFFECT` |
