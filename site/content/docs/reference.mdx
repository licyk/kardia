kardia 是 [Cordis](https://github.com/cordiverse/cordis) 的 Rust 移植。Cordis 是论文 [A Programming Paradigm for Spatiotemporal Composability](https://arxiv.org/abs/2608.25512) 所描述的 TypeScript 插件（plugin）框架。[概念](/docs/concepts)部分介绍论文的模型；本部分介绍**代码**：TypeScript 实现如何真正落实这一模型，在哪些地方细化或偏离了论文，以及移植时必须保留哪些部分。

这些页面描述的是 Cordis，而不是 kardia。上下文（`Context`）、纤程（fiber，`Fiber`）、效应（effect，`ctx.effect`）等名称以及 `cordis/packages/core/src/fiber.ts` 等路径都指 TypeScript 代码。kardia 如何把它们映射到 Rust，见[开发](/docs/development)部分。

<Callout type="info">
所分析的代码是位于 `cordis/` 的 TypeScript 检出（一个独立的 git 仓库，被外层仓库的 `.gitignore` 忽略），HEAD 为 `6663348 fix(fs-node): reject drive-relative paths on Windows (#285)`。`cordis` 核心包版本为 `4.0.0-rc.12`，即论文中的 "Cordis v4"。文件与行号引用（`reflect.ts:182-185`）均基于该版本。
</Callout>

## 工具链 [#tooling]

- Yarn 4 工作区（`external/*`、`packages/*`），仅 ESM，TypeScript 通过一个 `tsx` 分支直接执行。
- `yakumo` 构建编排器（`yakumo.yml`：`yakumo`、`yakumo-tsc`、`yakumo-esbuild`、`yakumo-vitest`）：`build` = esbuild 打包 + `tsc` 声明文件；`test` = vitest；另有覆盖率变体。
- Vitest 使用 `pool: 'forks'` 与 `--expose-internals`（hmr 需要；分叉进程使每个测试文件的模块缓存修改彼此隔离）。
- ESLint（`@cordisjs/eslint-config`）。
- CI（`.github/workflows/build.yml`）：lint（Node 26），在 `main` 上构建并发布，在 Ubuntu/Windows/macOS × Node 24/26 上运行测试。
