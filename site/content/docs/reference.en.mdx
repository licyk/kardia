kardia is a Rust port of [Cordis](https://github.com/cordiverse/cordis), the TypeScript plugin framework described in the paper [A Programming Paradigm for Spatiotemporal Composability](https://arxiv.org/abs/2608.25512). The [Concepts](/docs/concepts) section covers the paper's model; this section covers the **code**: how the TypeScript implementation actually realizes that model, where it refines or departs from the paper, and which parts a port must preserve.

These pages describe Cordis, not kardia. Names such as `Context`, `Fiber`, `ctx.effect` and paths such as `cordis/packages/core/src/fiber.ts` refer to the TypeScript code. How kardia maps them to Rust is covered in the [Development](/docs/development) section.

<Callout type="info">
The analysed code is the TypeScript checkout at `cordis/` (a separate git repository, ignored by the outer repository's `.gitignore`), at HEAD `6663348 fix(fs-node): reject drive-relative paths on Windows (#285)`. The `cordis` core package is version `4.0.0-rc.12`, the paper's "Cordis v4". File:line references (`reflect.ts:182-185`) are against that revision.
</Callout>

## Tooling [#tooling]

- Yarn 4 workspaces (`external/*`, `packages/*`), ESM only, TypeScript executed directly via a `tsx` fork.
- The `yakumo` build orchestrator (`yakumo.yml`: `yakumo`, `yakumo-tsc`, `yakumo-esbuild`, `yakumo-vitest`): `build` = esbuild bundles + `tsc` declarations; `test` = vitest; coverage variants.
- Vitest with `pool: 'forks'` and `--expose-internals` (needed by hmr; forked processes isolate module-cache mutation per test file).
- ESLint (`@cordisjs/eslint-config`).
- CI (`.github/workflows/build.yml`): lint (Node 26), build + publish on `main`, tests on Ubuntu/Windows/macOS × Node 24/26.

## The test suite as specification [#tests]

| Package | Spec files |
|---|---|

| loader | `evaluate.spec`, `rebuild.spec` (interleavings), `isolate*.spec`, `commit.spec`, `validate.spec` |
| include | `sync.spec` (journal/patch/merge matrix), `write.spec`, `location.spec` |
| hmr | `reconcile.spec`, `index.spec`, `watch.spec` |
