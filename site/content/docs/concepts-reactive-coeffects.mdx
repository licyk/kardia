本页概述论文（[arXiv:2608.25512](https://arxiv.org/abs/2608.25512)）的 §3.2。定义编号沿用论文。Cordis 的实现见 Cordis 参考中的[上下文与反射](/docs/reference-context)和[纤程生命周期](/docs/reference-fibers)。

空间可组合性（spatial composability）指组件能够声明依赖，系统能够在运行时解析、提供和撤回这些依赖。每当共享上下文发生变化，都必须重新评估依赖是否满足，使组件在依赖可用时激活、在依赖被撤回时停用。

## 余效应上下文（§3.2.1）

论文把控制反转（IoC）容器形式化为余效应（coeffect）上下文。

### 定义 19：余效应上下文

对类型族 `𝒱 : K → Type`，`Σ := (k : K) ⇀ 𝒱_k` 是一个**有限的依赖偏函数**。记号：`σ(k)` 表示应用，`σ[k ↦ v]` 表示扩展，`σ ∖ k` 表示限制，`k ∈ dom(σ)` 表示成员关系。类型族为每个键赋予一个静态的值类型。

**前置条件**：一个依赖不能被提供两次（扩展要求 `k ∉ dom(σ)`），也不能在不存在时被撤销（限制要求 `k ∈ dom(σ)`）。违反前置条件*会报告为错误，且不产生任何状态转移*（等价地，在 `Maybe` 单子中组合）。

### 定义 20：get / set

```text
get : (k : K) → Σ ⇀ 𝒱_k                     get(k)(σ)    = σ(k)                 requires k ∈ dom(σ)
set : (k : K) × 𝒱_k → Σ ⇀ Σ × (Σ ⇀ Σ)       set(k, v)(σ) = (σ[k ↦ v], λσ′. σ′ ∖ k) requires k ∉ dom(σ)
```

`set(k, v)` **是一个效应函数**（`𝔈Σ*`）。因此 §3.1 的效应机制（[可撤销效应](/docs/concepts-revertible-effects)）可以直接适用：依赖的注册会被自动追踪和恢复。*“余效应操作就是效应，而效应是可撤销的。”*

## 规约与通知（§3.2.2）

访问不存在的依赖是运行时错误，因此组件应当**只在其声明的全部依赖都存在时才激活**，而不是乐观地访问它们。

- **满足谓词**：`σ ⊧ d := ∀k ∈ d. k ∈ dom(σ)`，由于 `dom(σ)` 有限，它是可判定的。
- 由于对 `σ` 的每次修改都经过效应函数，满足性的变化在每个效应边界都可被检测到：*效应系统保证每一次余效应变化都会被观察到。*

### 定义 21：余效应规约（coeffect specification）

`𝔇Σ := Set(K)`。

### 定义 22：通知（notification）

```text
notify_d(σ, σ′) = activating    if σ ⊭ d ∧ σ′ ⊧ d
                  deactivating  if σ ⊧ d ∧ σ′ ⊭ d
                  neutral       otherwise
```

（三种结果分别为：激活、停用、中性。）激活转移会触发组件效应的执行（按 §3.1 追踪）；停用转移会触发通过累加器进行的恢复。

**局部空间可组合性**：组件只在满足其规约的状态下激活（从不读取不存在的绑定），并且每一次上下文变化都会依据规约进行分类（满足性的丧失在发生处即被检测到）。有两件事留给全局形式（§4.3.3，见[元理论](/docs/concepts-metatheory)）：只在一个绑定所引起的停用全部完成*之后*才撤回该绑定，以及在激活运行期间保持其所读取的绑定不变。

## 隔离与拦截（§3.2.3）

扁平的表无法为不同组件把*不同*的值绑定到同一个逻辑依赖上。论文为此增加了两个扩展。

### 实现方式（定义 23）

上下文上的效应函数有两种实现方式（realization）：

- **原地**（in-place）：修改上下文并返回一个非平凡的逆操作；恢复时运行该逆操作。
- **派生**（derived）：保持输入不变，返回一个*从它派生出的新上下文*，逆操作为恒等；恢复时丢弃派生上下文。

在纯函数式环境中两者一致；命令式宿主可以按操作选择。**隔离（isolation）与拦截（interception）采用派生实现**：它们产生一个子上下文，其自有表不同于继承来的表，共享表保持不变，因此无需追踪任何东西。在派生表上赋值会在该键上覆盖继承来的值，因此这两种操作都没有前置条件。

### 余效应隔离：定义 24、25

```text
Σ_iso := (K ⇀ R) × ((r : R) ⇀ 𝒱_r)        a pair (ρ, σ)
ρ : realm table; a key outside dom(ρ) resolves to its own realm (ρ(k) = k, R ⊇ K)
σ : dependency table indexed by realm

get(k)(ρ, σ)       = σ(ρ(k))
set(k, v)(ρ, σ)    = ((ρ, σ[ρ(k) ↦ v]), λ(ρ′, σ′). (ρ′, σ′ ∖ ρ′(k)))
isolate(k, r)(ρ,σ) = (ρ[k ↦ r], σ)          -- derived; reassigns rather than refuses
```

（`ρ` 是领域（realm）表，不在 `dom(ρ)` 中的键解析到它自己的领域；`σ` 是按领域索引的依赖表；`isolate` 采用派生实现，对已有的领域是重新分配而不是拒绝。）

两层解析 `k → ρ(k) → σ(ρ(k))` 把逻辑层与存储解耦。论文称之为**运行时特设多态**（runtime ad-hoc polymorphism）：同一个键在不同上下文中解析为不同的值，且可在运行时调整（多租户系统、测试、沙箱）。`set` 仍是效应函数（可撤销）；`isolate` 不需要逆操作。

### 余效应拦截：定义 26、27

拦截在不改变值的前提下，为依赖访问附加横切的**元数据**。

```text
Σ_inter := ((k : K) → ℳ_k) × ((k : K) ⇀ (ℳ_k → 𝒱_k))      a pair (ι, σ)
𝔇_inter := (k : K) ⇀ ℳ_k                                   specification carries metadata
Each key has a metadata monoid (ℳ_k, ⊕_k, ε_k).

get(k, μ)(ι, σ)       = σ(k)(μ ⊕_k ι(k))
set(k, ψ)(ι, σ)       = ((ι, σ[k ↦ ψ]), λ(ι′,σ′). (ι′, σ′ ∖ k))
intercept(k, ν)(ι, σ) = (ι[k ↦ ι(k) ⊕_k ν], σ)        -- derived
```

（规约此时携带元数据；每个键有一个元数据幺半群 `(ℳ_k, ⊕_k, ε_k)`；`intercept` 采用派生实现。）

- `ι` 是**上下文携带的**元数据（由外层上下文设置）；`σ(k)` 是一个从元数据到值的*提供者函数*；规约 `d(k)` 是**组件声明的**元数据。
- 访问时，系统计算 `σ(k)(d(k) ⊕_k ι(k))`。合并遵循各个键自己的语义（标量覆盖，集合取并），并且是**右偏**的：上下文携带的元数据优先，因此外层上下文可以在不修改组件的情况下约束组件如何使用某个余效应（用于 §6.3 的访问控制，见[讨论与相关工作](/docs/concepts-related-work)）。

## 工程要点

| 形式概念 | 实际含义 |
|---|---|
| `Σ` 作为依赖偏映射 | 按名称索引的服务注册表，每个键有固定的值类型。 |
| `set` 的前置条件 | 提供一个已被提供的键是错误（“单一来源”）。 |
| `set` 是效应 | `provide(name, value)` 返回一个撤销函数（disposer），并由外层作用域追踪。 |
| 满足性 / 通知 | 消费者只在每个依赖声明（inject）的键都可用时才启动；每次提供/撤回都会重新评估受影响的消费者。 |
| 派生实现 | `ctx.isolate(...)` / `ctx.intercept(...)` 返回一个*新的子上下文对象*；无需撤销任何东西。 |
| 领域 | 每个（作用域，键）对应一个不透明令牌；令牌相同意味着共享同一个绑定。 |
| 拦截合并 | 声明的元数据（在消费者的 `inject` 声明中）与上下文元数据合并；由外向内，内层优先。 |

<Callout type="info">
**在 kardia 中**：键是字符串 `Service::NAME`，通过 `Service` trait 绑定到一个 Rust 类型。`ctx.provide(value)` 是一个被追踪的效应，返回 `EffectHandle`；在同一领域中重复提供同一个键会以 `KardiaError::AlreadyProvided` 失败。`ctx.isolate(key)`（新的私有领域）、`ctx.isolate_in(key, realm)`（共享领域）和 `ctx.intercept(key, meta)` 返回一个派生的 `Context`。声明的元数据来自 `Inject::with_meta`，`Service::merge_intercept` 把它与上下文中的元数据由外向内合并，默认对 JSON 对象做右偏的浅合并。见[服务](/docs/guide-services)。
</Callout>
