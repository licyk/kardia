## Dependencies and ownership [#architecture]

<Mermaid chart={"flowchart LR\n  Server --> ACL\n  Server --> Echo\n  Server --> Static\n  Server --> Proxy\n  FS --> Static\n  Local[file provider] --> FS\n  HTTP[HTTP client] --> Proxy\n  Policy[Recovery supervisor] --> Fiber[Plugin lifecycle]\n  Fiber --> Effects[Routes streams sockets tasks]"} />

`kardia-server` uses Hyper 1.12 for HTTP/1 and tokio-tungstenite 0.30 for WS frames. Kardia controls routing, claimed responses and lifecycle. `kardia-http` uses Reqwest 0.13.5, rustls platform certificate verification and explicit streaming decompression, preventing library redirect/status defaults from changing upstream semantics. Production code does not invoke Node.

The `Svc` caller owns route, mount, connection and stream effects; services resolve dependencies at their definition site. In-flight HTTP handlers, middleware, route/upgrade hooks and response sources belong to cancellable task collections. Disposal unregisters, stops and awaits destruction before recovery creates another instance. Streams use bounded channels; reader/poll panics become operation errors.

Static reads through FS providers. Content detection owns a separate stream. Simple file-type rules and extension mappings are generated from fixed sources, while Rust stream readers handle complex containers. A source-hash check prevents unaudited upstream changes from entering generated mappings. The default POSIX detail of picomatch-rs 0.1.0 is adjusted against real comparisons.

## Isolation and recovery [#isolation]

[AGENTS.md](https://github.com/licyk/kardia/blob/main/AGENTS.md) makes isolation and configurable recovery mandatory. Manual is the default. Retry supervision lives outside the instance, waits for cleanup and uses a bounded rate. Host callbacks choose failure retention or delayed retry. Configuration errors do not loop. Policy changes, disablement, removal and disposal cancel old actions, and recovery does not rewrite configuration.

| Area | Real verification |
|---|---|
| Core supervision / loader | All policies, repeated failure, invalid configuration, synchronous/asynchronous host panic, cancellation and unknown handlers |
| Server | Handler panic before/after claiming; occupied-port startup failure/recovery under every policy while an independent Server handles HTTP |
| HTTP lifecycle | Pending callbacks, body sources, middleware, route hooks and upgrade hooks are destroyed before disposal completes |
| Echo / ACL | Repeated instance failure under every policy with healthy routes; Echo preserves the same healthy WS connection |
| FS / Static | Provider invocation/poll panic, first/later read errors, cancellation and non-local mounts; stream counters return to zero |
| HTTP client / Proxy | Repeated provider/instance failure under every policy, consumer rebuilding, continued healthy HTTP and the same healthy WS connection |
| Unavailable upstream | Current HTTP operation fails, WS never accepts; Proxy stays Active and works again without restart |
| Existing guest boundaries | Workspace regressions cover process exit/timeout/I/O panic, WASM and dylib paths; native dylibs are not described as crash-isolated |

Tests inject errors, panics or Fiber failure into the actual implementation and observe real sockets and cleanup counters. Automatic recovery does not use test-driven updates. Manual mode is observed Failed before explicit handling. Host mode follows callback decisions. Only the failed instance and consumers of unavailable services may be interrupted.

The containment boundary remains explicit: in-process unwind handling can catch Rust panic, but cannot contain abort, segfault or process-wide exit. Use the existing process/WASM guest boundary when that isolation is needed. This work does not add a sandbox for arbitrary native code.

## Fixed comparisons and reproduction [#parity]

Upstream comparisons live in the standalone `.github/workflows/server-reference.yml` workflow for manual verification. Select **Server reference → Run workflow** in GitHub Actions to run the Linux, Windows and macOS matrix. Its only trigger is `workflow_dispatch`; pushes, pull requests and releases do not invoke it. Regular Rust checks and failure-isolation tests remain in the main CI workflow.

Build the Rust host from the repository root, then run the existing tooling from `js/`:

```sh
cargo build -p kardia-server --example server-reference
cd js
bun install --frozen-lockfile
bun run server:prepare
bun run server:inventory --check
bun run server:mime --check
bun run check
bun run test:server:reference
```

Preparation verifies/builds the fixed upstream in ignored `cordis/`, installs immutable Yarn dependencies and runs the original suites. It does not reset an unknown upstream worktree. `inventory.json` counts declarations, not passing tests. Adapters register fixtures and drive real services; they do not reproduce the algorithms under test.

| Test category | Passing coverage |
|---|---|
| Original upstream suites | 105: core 57, ACL 15, Static 24, Proxy 9; Echo has no original independent suite |
| Supplement / dual-host network tests | 201: reference 22, HTTP 51, WS/Echo 5, ACL 26, Static 29, client 28, Proxy 25, handshake 15 |
| Content MIME detection | 254 files at fixture SHA `7fc6d9ff7cc01987aa73006757792a5ca198023a` plus 2 supplements, covering all 171 MIME values |
| Negotiation and globs | All 1,180 extensions; 26 Static configurations across 15 paths each; no semantic-difference normalization |
| Native platforms | Linux, Windows and macOS run Rust checks and actual upstream/comparison suites |
| CLI / catalog | A real CLI subprocess runs the example; catalog aliases, provider replacement and consumer rebuilding |

HTTP comparisons include status, reason, semantic headers and complete bodies; large files use full-body SHA-256. WS compares text/binary types, bytes, subprotocols and close code/reason. HTTPS/WSS uses a real certificate fixture, with separate rejection tests for untrusted certificates and hostname mismatch. Certificate verification is not bypassed.

## Relationship to upstream [#boundaries]

Observed upstream details are retained, including dropped custom reason text for returned Response, Proxy's last Set-Cookie, provider-context proxy publicUrl, and error-page path rules that differ from ordinary files. See the [behavior reference](/docs/reference-server).

Rust uses typed callbacks/services and UTF-8/serde values rather than reconstructing the entire JS object model. The auxiliary HTTP service covers HTTP(S)/WS(S) raw transport, configuration and lifecycle, not the complete decoder/file/data/SOCKS ecosystem; its WS client does not offer permessage-deflate. FS adds read-only provider streams and keeps existing watches, without a write ecosystem. All five target plugins have production implementations; no parallel JS products or guest network protocol were added.

When changing the upstream SHA, record behavior changes and update shared fixtures before regenerating mappings and running native parity and failure matrices. Keep rules, fixture provenance and reproducible commands available. Compilation or a successful host restart cannot replace isolation acceptance.
