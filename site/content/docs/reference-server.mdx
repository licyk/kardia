## 核心接口 [#core]

`kardia::server` 导出 `ServerPlugin`、`ServerConfig`、`Server`、`ServerExt`、`Request`、`Response`、`Body`、`Path`、`WsExt` 等。服务键为 `server`。

| 配置 | 行为 |
|---|---|
| `host` | 默认 `127.0.0.1` |
| `port` | 必填，允许 `0` 由系统分配 |
| `maxPort` | 默认起始端口；仅地址占用/权限错误时逐端口尝试 |
| `publicUrl` | 显式值去尾斜杠，再附加调用者 `intercept.server.path` |

自动 URL 使用实际端口；通配监听地址映射为 `127.0.0.1`。80/443 分别生成 http/https URL，但 URL 的 scheme **不表示监听器启用了 TLS**；服务端是 HTTP/1，TLS 可由前置宿主处理。HTTP 客户端支持 HTTPS 和 WSS。

`get`、`post`、`all` 注册便捷路由；`route(method, path, handler, options)` 支持 DELETE、HEAD、PUT、PATCH 等方法。顺序为注册顺序，GET 不隐式接受 HEAD。无匹配为 404，路径匹配但方法不同为 405；OPTIONS 为 204，`Allow` 使用小写方法和注册顺序，all 对应 `*`。

字符串路径支持参数、通配符、可选组和引号参数名，遵循 path-to-regexp 8.4.2；路径捕获值解码百分号转义并保留字面量 `+`；query 保留重复键，仍将 `+` 解码为空格。`Path::regex(source, flags)` 使用 ECMAScript 正则语法，支持 g/y 状态、UTF-16 匹配和 Unicode 标志。拦截前缀按字符串匹配，不额外要求路径段边界。

字符串 HTTP 路由的 `intercept.server.routes["METHOD path"]` 覆盖调用处 options，未覆盖字段保留；WS 和正则路由不应用这一覆盖表。

## 请求、响应与钩子 [#http]

- `use_middleware`、`on_route_request` 和 `Next` 组成可短路的异步链；`on_route_check` 返回 true 表示跳过路由，HTTP/WS 共用。
- `Request` 提供 method、url、path、query、headers、params，以及 bytes/text/json/blob/form_data。请求 body 只消费一次。
- `Response` 可设置状态、header、bytes/text/json/Blob/FormData/stream。显式状态或 body 标记 claimed；仅设置 header 不算完成响应。后一次 body 写入替换前一次。
- 普通异常或 unwind panic 在未 claimed 时返回 500；验证器的 `ValidationError` 返回 422 和 issues。已 claimed 的状态和内容保留。
- 返回 `Some(Response)` 时按上游采用 body、status 和 header，**不复制自定义 status text**，重复 Set-Cookie 只保留最后一个。直接对传入响应设置 status text 可以生效。
- `accepts` 使用固定上游 MIME 数据和协商优先级；JSON 输出采用 JS Number 格式及整数属性排序。需要保留超过 JS Number 精度的整数时使用字符串。
- 原生 Rust API 使用 UTF-8 字符串、serde JSON 值及类型化回调，不模拟 JS 原型、可调用对象或孤立 UTF-16 surrogate。Rust 读取 JSON 的值表示不等于完整 JS Number 运行时；响应编码按对照契约处理。

## WebSocket 与 Echo [#websocket]

`ws(path, handler, options)` 注册路由。省略 handler 自动 accept；显式 handler 必须调用 `accept.accept().await`。没有 accept 则断开，accept 前异常返回 500，accept 后异常关闭连接。无匹配路由返回 404。

有效握手接受版本 13/8，选择首个请求子协议；非法 method、key、version 和 protocol 的状态、错误 body 与 header 已与上游对照。服务端最大消息为 100 MiB。`WebSocket::send/recv/close` 使用类型化 Message，保留文本/二进制及关闭原因。路由释放关闭自己的连接并回收任务。

Echo 只注册空路径 POST 和 WS，通过 intercept 挂载。HTTP 流式复制 body 及 content-type；WS 保留消息类型和字节。

## ACL [#acl]

`AclPlugin` / `AclConfig` 的 `allowedHosts` 缺省或 true 表示放行；false 仅允许 loopback；数组额外允许列出的域名。忽略大小写和端口，识别方括号 IPv6；`.example.com` 同时匹配裸域与子域。单条路由 options 替换组件的 allowedHosts，不合并列表。

拒绝表示继续查找后续路由，全部拒绝时为 404，不改成 403，也不暴露被拒路由的 Allow。此规则同时适用于 HTTP 和 WS。

## Static [#static]

`StaticPlugin` / `StaticConfig` 依赖 `server` 与 `fs`，从 provider 读取，不绕过文件服务直接访问磁盘。

| 配置 | 默认与行为 |
|---|---|
| `root` | 必填；相对 fs.baseUrl 按目录解析，清除查询和片段 |
| `index` | `["index.html", "index.htm"]`，按顺序尝试 |
| `redirect` | true；目录缺少尾斜杠时 301 |
| `extensions` | 空；原文件优先，再按顺序尝试扩展名 |
| `exclude` | 空；按相对 URL 路径匹配，包含点文件 |
| `fallthrough` | false；启用时仅 404 继续后续路由 |
| `disposition` | 未配置；可用 inline / attachment |
| `errorPages` | 空；按状态码选择错误页，保留原状态 |

缺失、非目录、目录和 InvalidPath 对应 404，PermissionDenied 对应 403，其他读取错误为 500。错误页沿用上游独立的解析路径，不套用普通文件的 exclude/containment 或下载 disposition；不要将它误当作与普通请求相同的路径规则。

MIME 顺序为内容检测、文件名、octet-stream。固定 file-type 20.5.0 的全部 171 个 MIME 值有真实样本覆盖；检测使用独立可取消流，支持小块数据和跨越首块的容器头。扩展名表与 picomatch 排除规则均有上游对照。attachment 使用 UTF-8 文件名编码。

## Proxy [#proxy]

`ProxyPlugin` / `ProxyConfig` 依赖 `server` 与 `http`，必填 `target` 按目录解析。即使配置 URL 含查询或片段，也在 pathname 上补尾斜杠。解码后的路径逐段重新编码，保留 `+` 和路径段子分隔符；`?`、`#`、`%` 保持为路径内容。规范化后的目标必须仍在同一 origin 和目标目录内；越界 HTTP 返回 400，WS 直接断开且不连接上游、不接受下游。query 以 URLSearchParams 规则编码并替换目标查询。

HTTP 转发方法与 header，仅 POST/PUT/PATCH 转发 body。原始客户端保留 4xx/5xx，并按 Fetch 重定向规则处理流式 body。解压后的响应移除 content-encoding/content-length。上游核心采用返回 Response 的行为也被保留：自定义 reason 不转发，重复 Set-Cookie 只留下最后一个。

WS 先连接上游再 accept 下游，过滤 Host、Connection、Upgrade、握手 key/version/extensions/accept 和 content-length。文本与二进制双向转发；关闭码 1000 或 3000–4999 原样传递，其他转换为 1000。上游传输错误关闭下游为 1011；握手连接失败不 accept，不自行改成 502。

`ServerProxy` 的服务键为 `server.proxy`，`public_url()` 从**提供插件的上下文**读取 Server，因此包含它的挂载前缀；后续消费者的 intercept 不改变该 getter。HTTP/Server 替换时 Proxy 按依赖关系重建。普通上游连接失败只影响本次操作，上游恢复后健康 Proxy 实例可继续使用。

## 辅助服务范围 [#auxiliary]

`FsExt` 增加 `base_url`、`resolve`、`file` 和 `mount`；配置 base 与从外到内的每层拦截都视为目录 URL：pathname 以 `/` 结尾，清除 query/fragment，拒绝 `mem:bucket` 等不支持相对解析的 opaque base。因此 `file:///app` → `data` → `logs?x#y` 最终指向 `file:///app/data/logs/`。Windows 绝对盘符路径在输入边界转换为 file URL；未知配置字段仍可保留。最长挂载前缀优先。`LocalFsPlugin` 显式挂载 file:，保留原生 watch 功能。本轮没有扩展 FS 写入/删除/重命名生态。

`HttpExt::request` 返回 raw status、reason、headers 和流 body；`WebSocketExt::ws` 提供客户端连接。配置支持 baseUrl、headers、timeout、keepAlive、proxyAgent 和附加 PEM rootCertificates。拦截按上游规则合并，请求 headers 替换配置 headers。超时约束到响应头收到为止；body 仍归调用者生命周期。TLS 使用平台证书验证并可添加信任根，不关闭验证。

支持 gzip、deflate（zlib/raw）、Brotli、Zstd 解压，原始响应仍保留压缩 header 供调用方决定转发方式。辅助客户端不覆盖完整 HTTP decoder、file/data URL 或 SOCKS 生态；WS 客户端不提出 permessage-deflate 协商，应用消息语义已对照。生产路径全部为 Rust，Node 仅用于测试上游。
