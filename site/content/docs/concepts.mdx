kardia 实现的是论文 *A Programming Paradigm for Spatiotemporal Composability*（[arXiv:2608.25512](https://arxiv.org/abs/2608.25512)；92 页；Shi、Zhang、Cui；北京大学与 DeepSeek-AI）中的模型。本部分概述论文的理论：先介绍其问题陈述、贡献和术语，然后论文的每一部分各占一页。定义、定理、引理和算法的编号始终沿用论文。

本部分不描述 Cordis 代码库（见 [Cordis 参考](/docs/reference)），也不描述 kardia 的 Rust 设计（见[开发](/docs/development)）。当某个概念在 kardia 中有直接对应时，会有一个“在 kardia 中”的提示框加以说明，并链接到相关页面。

## 问题陈述

静态组合（函数调用、导入、继承）在编译期就已固定。插件系统和*自我演化的智能体框架*（self-evolving agent harnesses）需要**动态组合**：组件在进程持续运行时被加载、卸载和重新配置。论文认为，除了组合的代数方面之外，动态组合还有两个正交的维度（§1.1）：

| 维度 | 要求 | 静态对应物 |
|---|---|---|
| **时间可组合性**（temporal composability） | 当一个组件被移除时，它对共享环境所做的每一处修改（资源、事件注册、状态变更）都被完整、安全、有序地撤销。 | 词法作用域：RAII、bracket 模式 |
| **空间可组合性**（spatial composability） | 组件以结构化、可验证的方式声明、发现和解析彼此之间的依赖；当依赖出现、消失或改变身份时，各组件的生命周期得到协调。 | 模块导入解析 |

### 动机示例（§1.2）

- **VSCode**：扩展无法单独卸载（排名前 100 的扩展中有 87 个包含代码，需要重启扩展宿主）；`deactivate` 只是一个关闭钩子，把释放与创建割裂开来。`extensionDependencies` 几乎没人使用（前 100 中只有 7 个），扩展间的 API 是无类型的（`exports: any`）。
- **智能体框架**：一个持续改写自身组件的框架无法承受每次修改都重启一次，而朴素的代码替换会悄无声息地破坏依赖者。
- **粗粒度的变通办法**：操作系统进程以进程为单位提供时间可组合性；容器编排器以服务为单位提供空间可组合性。二者在重启时都会丢弃进程内状态，也无法表达同一地址空间内的依赖；粒度是错的。

## 核心思想

效应（effect）系统描述计算如何**修改**其环境；余效应（coeffect）系统描述计算**需要**环境提供什么。二者传统上都是*静态*的（在词法固定的作用域上检查）。论文把二者都**具体化**为运行时对象：

1. **可撤销效应**（§3.1）：每一次上下文变换都与一个由运行时持有的逆操作配对。追踪和恢复都是幺半群同态，因此组件被移除时上下文得以恢复，从而带来*局部时间可组合性*。
2. **响应式余效应**（§3.2）：组件声明它所需要的键（一份*规约*）；每一次上下文变化都依据规约被分类为*激活*、*停用*或*中性*，由此驱动激活与停用。这带来*局部空间可组合性*。
3. **上下文范式**（§3.3）：效应上下文与余效应上下文被统一为一个上下文类型 `Γ∞`，*所有*效应与余效应都经由它中介。这诱导出一个**观察等价 `≃`**，在它之下，不同组件的效应变得**独立**（§3.4）。
4. **动态组合演算**（§4）：组件是一个三元组 `(d, p, e)`（依赖、提供、效应迭代器）；它的实例是**纤程**（fiber）；九条规则（3 条编排规则、6 条生命周期规则）让纤程经历 `Inactive → Reloading → Active → Unloading`。元理论证明了保持性、恢复精确性、顺序性、解析一致性、进展性（无死锁且终止）以及**合流性**（静止状态等于从零开始静态加载最终配置所得的状态）。
5. **Cordis**（§5）：一个 TypeScript 元框架，由核心库（效应追踪与余效应解析）和一个带配置协调与模块热替换的声明式加载器组成。案例研究：**Koishi**，一个拥有超过 4000 个社区插件的聊天机器人框架（Koishi 使用 Cordis v3；论文描述的是 v4）。

## 预备知识（§2）简述

- **效应**。判断形式为 `Γ ⊢ t : T ! effect`。单子效应（Moggi、Wadler）把带效应的计算封装在 `T(A)` 中，带有单位 `η` 和乘法 `μ`。代数效应（Plotkin 与 Power）声明操作签名；效应处理器（Plotkin 与 Pretnar）用定界延续来解释它们（Koka、Eff、OCaml 5）。
- **余效应**。判断形式 `Γ @ coeffect ⊢ t : T` 标注的是*上下文*。余单子 `(D, ε, δ)`（Uustalu 与 Vene）为依赖上下文的计算提供结构；Petricek 等人提出把余效应作为一种统一的静态分析；分级余效应使用预序半环来量化使用情况。
- **缺口**。二者都是作用于词法固定作用域的静态工具。没有任何固定的词法作用域能界定一个在部署之后才加载的插件，也没有任何编译期上下文能预见由运行时配置产生的依赖。因此论文把这些结构*具体化*，使运行时能够操作它们，并在动态中确立这些系统在静态中所保证的东西。

## 术语表

论文的术语：

| 术语 | 含义 |
|---|---|
| 上下文类型 `Γ` | 类型上下文在运行时可操作的具体化；`Γ∞ = μΓ. Γ × (Γ→Γ) × Σ`。 |
| 效应上下文 `∂Γ` | `Γ × (Γ→Γ)`：一个状态加上一个*累加器*（逆操作的复合）。 |
| 累加器 `φ` | 把上下文恢复到初始状态的函数；逆操作按 LIFO 的复合。 |
| 效应函数 `𝔈Γ` | `Γ → Γ × (Γ→Γ)`：返回新状态和一个针对该状态的逆操作。当逆操作可证明地在被应用的状态下撤销该效应时，称其带见证（`𝔈Γ*`）。 |
| 效应迭代器 `ℑΓ` | `μℑ. Γ → Γ × (Γ→Γ) × Maybe(ℑ)`：一个效应序列，相邻迭代之间有边界；一种具体化的定界延续（生成器）。 |
| 余效应上下文 `Σ` | 有限的依赖偏映射 `(k:K) ⇀ V_k`。 |
| 规约 `d` | `Set(K)`：组件所需的键。 |
| 提供 `p` | `Set(K)`：组件可以设置的键。 |
| `notify_d(σ, σ′)` | 对一次转移的分类：激活 / 停用 / 中性。 |
| 隔离领域（realm） | `ρ : K ⇀ R`；键 → 领域 → 值（两层解析）。 |
| 拦截元数据 | 每个键一个幺半群 `(M_k, ⊕_k, ε_k)`；按 组件声明的 `⊕` 上下文携带的 合并（右偏）。 |
| 余效应操作 `𝒜_k` | 键 `k` 上的值所提供的操作；它们诱导出观察等价 `≃_k`。 |
| 可交换键 | 该键上的所有操作两两独立；*带见证的余效应*携带这一证明。 |
| 组件 `ℭΓ` | 三元组 `(d, p, e)`。 |
| 纤程 | 实例 `⟨d, p, e, π, σ, τ, θ⟩`（父纤程、自有表、退役标志、生命周期状态）。 |
| 生命周期状态 `θ` | `Inactive \| Reloading(i,g,ω) \| Active(g,ω) \| Unloading(g,ω)`。 |
| 已提交视图 `ω` | 在提交时把声明的键映射到*提供该键的纤程的名字*的映射。 |
| 目标视图 | `ω` 现在应当是什么（若已退役或依赖未满足则为 `⊥`）。 |
| 守卫（`relied_n`） | 只有当没有任何已安装纤程的已提交视图指向 `n` 时，L-Unload 才能触发。 |
| 静止（quiescent） | 每个纤程都在其目标处稳定下来。 |
| 支撑集 `A` | 未退役、父纤程受支撑、且其声明的键都由受支撑纤程提供的那些纤程。 |
| 惯性（inertia） | 异步宿主无法中止正在进行的迭代；只有 L-Divert 的*落地*选项可用。 |
| 系统边界 | 系统能够独占地修改并恢复的位置在内部；其他位置在外部（外发会跨越边界）。 |
