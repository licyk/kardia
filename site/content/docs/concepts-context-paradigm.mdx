本页概述论文（[arXiv:2608.25512](https://arxiv.org/abs/2608.25512)）的 §3.3–3.4。这一部分把*局部*保证（单个组件，见[可撤销效应](/docs/concepts-revertible-effects)与[响应式余效应](/docs/concepts-reactive-coeffects)）转化为*全局*保证（多个交错运行的组件，§4.3，见[元理论](/docs/concepts-metatheory)）的前提。

## 统一上下文（§3.3.1）

### 定义 28：上下文类型

```text
Γ∞ := μΓ. Γ × (Γ → Γ) × Σ
```

三个投影分别是当前状态（递归）、撤销本层效应（effect）的累加器，以及余效应（coeffect）上下文。`effect` 把 `𝔈Γ∞` 映射到自身，把 `∂` 塔折叠为一个自相似的类型。由于值类型族 `𝒱` 不受限制，**任何共享可变状态都可以编码为一个依赖**：`Σ` 涵盖所有共享状态，而不只是组件间的依赖。*组件与其环境之间的每一次交互都经过这一个实体。*

### 定义 29：余效应 = （值类型，操作）

键 `k` 上的余效应是一对 `(𝒱_k, 𝒜_k)`；每个参数为 `X_a`、结果为 `B_a` 的操作 `a ∈ 𝒜_k` **只作用于值本身**：

```text
a : X_a → 𝒱_k ⇀ 𝒱_k × (𝒱_k ⇀ 𝒱_k) × B_a
```

也就是说，它是值上的一个效应函数再加一个结果。它在 `Σ` 上的提升（式 31）只读写键 `k` 上的绑定：类型把操作限制在它自己的键上。依赖于另一个键的操作必须把那个键的值读入自己的参数。操作诱导出一个等价关系 `≃_k`（§3.3.2，见下文）。

### 定义 30：上下文中介迭代器 `ℑ^𝒜_Σ(S, P)`，`P ⊆ S ⊆ K`

包含单位元、并对两种**阶段**形式封闭的最小迭代器集合：

- **操作阶段**：对 `k ∈ S` 执行 `a ∈ 𝒜_k`，并根据结果选择延续；
- **提供阶段**：对 `k ∈ P` 执行 `set(k, v)`（这是任何操作都无法创建的键）。

属于这一类，*正是*“通过上下文中介每一次交互”的形式含义。任何读取未被任何键绑定的位置的东西（例如一个从上下文未携带的计数器中分配句柄的分配器）都在这一类之外；一旦那个计数器被绑定到它自己的键上，它就变成被中介的了。

### 层次化组合

递归结构形成一棵树：加载组件就是执行它的效应（插入）；卸载就是撤销这些效应而不影响其他组件；父组件汇总其所有子组件的效应，从而允许任意嵌套。

## 观察等价（§3.3.2）

定理 7 中的状态相等是一种理想化：`free` 不会恢复堆布局，新分配的名字也不会被“收回”。因此相等关系应**在观察等价 `≃` 的意义下**理解：当没有观察者能区分两个状态时，它们相关。上下文的观察者拿到的是它的余效应；值的观察者拿到的是其键上的操作。

- **定义 31：测试 / 不可区分性。** `𝒜` 上的一个*测试*是由操作的正向映射与其产出的逆操作组成的有限字；当每个测试在两者上都有定义或都无定义、且产生相同结果时，记 `v ≈_𝒜 v′`。`≃_k := ≈_{𝒜_k}`。
- **引理 32**：`≃_k` 是一个被 `𝒜_k` 中所有操作保持的等价关系，并且是此类关系中*最粗*的（证明原则：给出任意一个包含该对的、被保持的等价关系即可）。
- **定义 33**：在键集 `S` 上相关的状态在 `S` 上有相同的定义域，且在每个键上的值相关。`≃`（`S = K`）最细；`≃_S` 忽略 `S` 以外的键。相关的状态在满足性和 `notify_d` 上一致，因此*响应性是 `Σ/≃` 的性质*。
- **定义 34**：`≃` 在函数、积和 `Maybe` 上的逻辑关系扩展，对迭代器按余归纳理解。一个映射与自身相关时，称它*保持* `≃`。
- **引理 35**：在映射和迭代器上，`≃_S` 是部分等价关系。
- **定义 36/37**：*在 `≃_S` 意义下带见证*的效应函数和迭代器：用 `g(δ) ≃_S γ` 代替相等。
- **引理 38**：把 §3.1 中所有等式的 `=` 换成 `≃` 后依然成立。
- **引理 39**：上下文中介迭代器属于 `ℑ^S_Σ`，其中 `S` 是任意包含其各阶段所触及键的集合。

## 独立性（§3.4.1）

定理 16 没有覆盖两种情况，需要独立性：在*之后的*效应仍然存在时运行一个逆操作（从运行中的系统中移除一个组件），以及多个组件的效应交错进行。

- **定义 40**：`reach(i)` 是通过延续可达的迭代器集合；变换幺半群 `𝔐(i)` 由 `reach(i)` 中所有正向映射与产出的逆操作生成；`len(i)` 是最长的延续链。
- **引理 41**：交换性在生成元上即可判定；`⋄` 不会扩大该幺半群。
- **定义 42：独立的迭代器** `i, j`：
  1. 一方的每个变换与另一方的每个变换可交换（对 `f ∈ 𝔐(i), g ∈ 𝔐(j)` 有 `f ∘ g = g ∘ f`）；
  2. 任何一方都不干扰另一方*产出*的东西（逆操作与延续）：`pr₂,₃(i′(g(γ))) = pr₂,₃(i′(γ))`。
- **定理 43**：对两两独立的 `e₁…eₙ`，**以任意排列**应用它们产出的逆操作，都能到达 `γ₀`。无论顺序如何，每个逆操作都只撤回它自己的贡献。

## 余效应交换性（§3.4.2）

- **定义 44**：当两个操作 `a, a′` 的提升是独立的效应函数，*并且*任何一方都不干扰另一方的结果时，称它们独立。当一个键上任意两个操作（包括操作与自身）都独立时，称该键是**可交换的**。
- **定理 45**：**不同键**上的操作总是独立的（键局部的映射可交换）。
- **定义 46：带见证的余效应**：余效应携带一个证明其键可交换的证据，作为第三个组成部分。与效应的见证一样，*这一义务落在提供该键的组件上*，而不是消费者。此后假定所有余效应都带见证。

### 驱动设计决策的例子

| 键上的值 | 可交换？ | 原因 |
|---|---|---|
| 每次注册都分配一个**新 id** 的条目表（路由、事件监听器） | **是** | 两次注册对应两个条目；无论顺序如何，每个测试的回答都相同；任一条目都可在另一条目保留时被撤回。（与 CRDT 为每次添加打上唯一标签的原因相同。） |
| add/remove 只指明一个裸元素的集合 | 否 | 在两次 `add(x)` 之后移除 `x`，无法分辨要移除的是谁的 `x`。 |
| 有序的中间件链 | **否** | 插在另一个中间件之前的中间件看到的是不同的请求。顺序必须由外部施加（组件内部由累加器，组件之间由声明的余效应）。 |
| 句柄从不被比较的分配器 | 是（在重命名意义下） | `≃_k` 在句柄重命名的意义下关联堆（参见 CompCert）。 |
| POSIX `open`（最小的空闲 fd） | 否 | 下一次分配的结果可以区分两种顺序。`mmap`/`creat` 则没有问题。 |

*接口设计规则（来自定义 31）*：公开更少的结果会使 `≃_k` 更粗；隐藏调用者不需要的结果可以使一个键变得可交换（参见可扩展交换性规则（scalable commutativity rule））。

- **定理 47**：两个上下文中介迭代器，若满足 `P₁ ∩ S₂ = P₂ ∩ S₁ = ∅`（任何一方都不提供另一方触及的键），且共享的键都可交换，则它们独立。当所有余效应都带见证时，只剩这一不相交条件需要检查，而 §4（[演算](/docs/concepts-calculus)）从声明中直接读出它。

### 这种分解达成了什么

计算中的**可交换部分**由效应承载：可以按任意顺序执行，也可以按任意顺序撤销（定理 43）。**顺序敏感部分**由余效应承载：组件内部由累加器施加 LIFO 顺序；组件之间由声明的余效应施加“提供者先于消费者”。因此，可组合性是在组件粒度上，而不是在单个效应粒度上获得的。

**局限**：把每个共享位置都绑定到一个键上是一种*纪律*，而不是该构造本身的性质。系统无法具体化为余效应的位置不在该定理的范围内（见[讨论与相关工作](/docs/concepts-related-work)中 §6.1 的系统边界）。

## 工程要点

- 把每个共享注册表都设计成“**以新 id 插入，按 id 删除**”。这正是使键可交换、让组件能以任意顺序卸载的条件。
- 顺序敏感的结构（中间件链、优先级列表）要么只归单个组件所有，要么把顺序显式化（例如显式的优先级值），使可观察的结果不依赖于插入顺序。
- 不要让组件绕过上下文去访问共享状态；任何绕过上下文的访问都不在这些保证之内。

<Callout type="info">
**在 kardia 中**：`kardia_core::IdTable<T>` 就是这种注册表：`insert` 返回一个新的、永不复用的 id，`remove` 接收这个 id，条目保持插入顺序。服务作者应当在它之上构建自己的注册表（路由、监听器、命令）。见[服务](/docs/guide-services)与 [API 设计](/docs/development-design)。
</Callout>
